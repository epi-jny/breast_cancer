Le pipeline de finetuning GMIC, ligne par ligne

Wrapper modèle, boucle d’entraînement et dataset — chaque ligne expliquée

Ce document explique chaque ligne des trois fichiers qui composent le pipeline de finetuning GMIC du projet RSNA cancer du sein :

  1. fine_tuning/gmic_finetune.py — le wrapper modèle (forward d’entraînement, construction, groupes de paramètres, gel du backbone) ;
  2. fine_tuning/train_gmic.py — la boucle d’entraînement intégrale (loss, évaluation par sein, augmentation GPU, scheduler, AMP, early-stopping, CLI) ;
  3. fine_tuning/dataset_gmic.py — le dataset intégral (construction des échantillons, augmentation CPU, sampler équilibré, split patient, loaders).

On mélange deux niveaux de lecture :

  • 🧠 la théorie (pourquoi sigmoïde + BCE, pourquoi z-score, pourquoi WeightedRandomSampler, pourquoi int16, etc.) ;
  • 💻 le vrai code du projet, recopié tel quel dans des blocs marqués « extrait réel ».

Les blocs « extrait réel » ne sont pas exécutés (ils dépendent du repo GMIC + données + GPU). Les blocs ▶️ démo jouet s’exécutent avec juste torch / numpy sur CPU et illustrent un concept en miniature.

Convention : dans chaque extrait, on numérote les lignes ou petits groupes de lignes (1), (2), … et on les commente juste en dessous. Rien n’est survolé.

0. Vue d’ensemble du pipeline

Avant de plonger dans le code, le schéma global. Trois fichiers, trois rôles :

  dataset_gmic.py          gmic_finetune.py            train_gmic.py
  ──────────────           ─────────────────           ──────────────
  data.pkl                 GMICTrain(GMIC)             main() / argparse
   │  load_and_split3        forward -> 3 têtes          build → freeze → optimizer
   ▼  (train/abstain/val)    + saliency                 boucle epochs :

   ▼                        freeze_backbone                evaluate (AUC par SEIN)

L’unité de données est la VUE (GMIC traite une image à la fois), mais la métrique de sélection est le SEIN (on moyenne les vues CC+MLO d’un même côté). Cette distinction « per-view vs per-breast » revient partout — gardez-la en tête.

1. L’architecture GMIC en une page (contexte conceptuel)

GMIC (Globally-aware Multiple Instance Classifier, NYU) est un classifieur de mammographies full-résolution (ici 2944×1920). Le naïf « je passe une image 2944×1920 dans un ResNet » est trop coûteux en mémoire. GMIC contourne ça avec deux branches + une fusion :

  image full-res (1, 2944, 1920)
        │
        ▼
  ┌─────────────────┐   branche GLOBALE
  │  ds_net (ResNet)│──► feature map ──► left_postprocess_net (conv 1x1)
  └─────────────────┘                     │  = saliency maps par classe
                                          ▼
                             aggregation top-t%  ──► y_global (proba)
                                          │
        ┌─────────────────────────────────┘  (saliency détachée)
        ▼
  retrieve_roi_crops : greedy ROI, NON différentiable (numpy) ──► K=6 patchs
        │
        ▼
  ┌─────────────────┐   branche LOCALE
  │ dn_resnet(R-18) │──► h_crops (K vecteurs)
  └─────────────────┘        │
                             ▼
                   attention_module (MIL) ──► z, y_local (proba)
                             │
        global_vec ──────────┤
                             ▼
                   fusion_dnn (Linear) ──► sigmoid ──► y_fusion (proba)

Les concepts à retenir :

  • Branche globale (ds_net) : un ResNet qui regarde l’image entière en basse résolution interne et produit une saliency map (carte de chaleur) par classe. L’agrégation top-t % prend la moyenne des t % pixels les plus chauds → proba globale y_global.
  • Region proposal (retrieve_roi_crops) : à partir de la saliency map détachée du graphe, une recherche gloutonne en numpy sélectionne les K=6 régions les plus saillantes. C’est non différentiable (aucun gradient ne remonte par le choix des coordonnées) et ce module n’a aucun poids.
  • Branche locale (dn_resnet, un ResNet-18) : applique un vrai ResNet haute-résolution sur chacun des K patchs 256×256 → K vecteurs de features.
  • Attention MIL (attention_module) : Multiple Instance Learning — pondère les K patchs par une attention apprise, agrège en un vecteur z et une proba y_local. Le MIL est l’idée « l’étiquette est au niveau de l’image, pas du patch ; le réseau apprend seul quels patchs comptent ».
  • Fusion (fusion_dnn) : concatène le vecteur global et z, passe dans un petit Linear + sigmoïde → y_fusion, la sortie principale.

Où vivent les poids (crucial pour le gel). Les deux gros extracteurs sont enregistrés sur le module parent sous les noms ds_net (global) et dn_resnet (local). Tout le reste (left_postprocess_net, attention_module, fusion_dnn) est la tête légère. Ces noms suffisent à isoler le backbone (cf. §4).

Cette section reste conceptuelle : ce code-là est upstream NYU. Ce qu’on documente ligne par ligne, c’est le wrapper du projet par-dessus.

2. gmic_finetune.py — le wrapper modèle

2.1 En-tête et imports

# === extrait réel : gmic_finetune.py ===
import torch                                          # (1)
import torch.nn as nn                                 # (2)

from src.modeling.gmic import GMIC                     # (3)

(1) torch : le cœur de PyTorch (tenseurs, autograd, CUDA). (2) torch.nn as nn : le sous-module des couches/réseaux (nn.Module, nn.functional.dropout, etc.), aliasé nn par convention. (3) from src.modeling.gmic import GMIC : importe la classe GMIC upstream. Le src.modeling... ne résout que si le dossier GMIC/ du repo est dans sys.path — c’est le script d’entraînement (train_gmic.py, §3.3) qui l’y insère avant d’importer ce module. D’où le commentaire du docstring : « ce module suppose que GMIC/ est dans sys.path ».

2.2 class GMICTrain(GMIC) — pourquoi sous-classer

Le GMIC d’origine renvoie surtout y_fusion et garde des buffers de visualisation (il fait des .cpu().numpy() pour dessiner les heatmaps). Pour l’entraînement, on veut :

  • renvoyer les 3 têtes y_fusion, y_global, y_local + la saliency_map (la loss supervise les trois, cf. §3.1) ;
  • éviter les copies CPU inutiles (pas de self.patches en numpy) ;
  • ajouter des augmentations train-only (rotation des patchs, dropout fusion).

On ne réécrit donc que le forward ; tout le reste (construction des sous-réseaux, add_layers, _retrieve_crop…) est hérité de GMIC.

# === extrait réel : gmic_finetune.py / class GMICTrain(GMIC) ===
class GMICTrain(GMIC):                                                       # (1)
    """GMIC avec un forward d'entrainement (multi-tete, sans buffers de visu)."""
    def forward(self, x_original):                                           # (2)

(1) GMICTrain(GMIC) : héritage. GMICTrain est un GMIC, avec un forward différent. Le __init__ n’est pas redéfini → on hérite de celui de GMIC (qui construit global_network, local_network, greffe ds_net/dn_resnet, etc.). (2) forward(self, x_original) : la méthode appelée quand on fait model(x). x_original est le batch d’images full-res (B, 1, 2944, 1920).

2.3 Le forward, ligne par ligne

Branche globale

# === extrait réel : gmic_finetune.py ===
        # --- branche globale ---
        h_g, self.saliency_map = self.global_network.forward(x_original)     # (1)
        self.y_global = self.aggregation_function.forward(self.saliency_map) # (2)

(1) self.global_network.forward(x_original) : passe l’image entière dans la branche globale (le ResNet ds_net + post-traitement). Renvoie deux choses : h_g, la feature map brute (réutilisée à la fusion, §2.3 fusion), et self.saliency_map, la carte de saillance par classe. On les stocke comme attributs (self.) car la loss régularise la saliency (§3.1) et le region proposal la réutilise. (2) self.aggregation_function.forward(self.saliency_map) : agrégation top-t % — moyenne des t % pixels les plus chauds de la saliency → la proba globale y_global. C’est une opération bornée (moyenne de valeurs déjà passées par une activation) → y_global est déjà une proba dans [0,1]. À retenir pour la loss (BCE, pas BCEWithLogits).

Region proposal (non différentiable)

# === extrait réel : gmic_finetune.py ===
        # --- region proposal (non differentiable, numpy) ---
        small_x_locations = self.retrieve_roi_crops.forward(                 # (1)
            x_original, self.cam_size, self.saliency_map)
        self.patch_locations = self._convert_crop_position(                  # (2)
            small_x_locations, self.cam_size, x_original)

(1) retrieve_roi_crops.forward(...) : la recherche gloutonne des K régions les plus saillantes. Elle travaille en numpy sur la saliency détachée → aucun gradient ne passe par le choix des coordonnées. self.cam_size est la taille de la carte d’activation (46, 30) (cf. default_parameters). Renvoie small_x_locations : les positions des ROI dans la grille basse-réso. (2) _convert_crop_position(...) : convertit ces positions de la grille cam_size vers les coordonnées en pixels de l’image full-res x_original. Résultat self.patch_locations : où découper les patchs dans l’image originale.

Extraction des K patchs

# === extrait réel : gmic_finetune.py ===
        # --- extraction des patchs (pas de copie self.patches) ---
        crops_variable = self._retrieve_crop(                                # (1)
            x_original, self.patch_locations, self.retrieve_roi_crops.crop_method)
        batch_size, num_crops, I, J = crops_variable.size()                  # (2)

(1) _retrieve_crop(...) : découpe effectivement les K patchs dans l’image full-res aux positions calculées. crop_method dit comment découper (centré, etc.). On garde le résultat en tenseur GPU (crops_variable), sans copie CPU numpy — c’est le « pas de copie self.patches » du commentaire, gain de temps à l’entraînement. (2) crops_variable.size() déballe les 4 dimensions du tenseur : batch_size (B images), num_crops (K=6 patchs par image), I et J (hauteur et largeur d’un patch, ici 256×256). On en aura besoin pour la rotation et le reshape.

Augmentation train-only : rotation des patchs

# === extrait réel : gmic_finetune.py ===
        # --- augmentation papier : rotation aleatoire {0,90,180,270} de chaque patch ---
        if self.training and I == J:                                         # (1)
            ks = torch.randint(0, 4, (batch_size, num_crops))                # (2)
            crops_variable = torch.stack([                                   # (3)
                torch.rot90(crops_variable[i, j], int(ks[i, j]), dims=(0, 1))
                for i in range(batch_size) for j in range(num_crops)
            ]).view(batch_size, num_crops, I, J)                             # (4)

(1) if self.training and I == J: — deux garde-fous. self.training est le drapeau basculé par model.train() / model.eval() : l’augmentation ne se fait qu’en entraînement (jamais en évaluation, où on veut un résultat déterministe). I == J vérifie que le patch est carré : une rotation de 90° sur un patch non carré changerait la forme du tenseur. (2) torch.randint(0, 4, (batch_size, num_crops)) : tire un entier aléatoire dans {0,1,2,3} pour chaque patch de chaque image (matrice B×K). Ce sera le nombre de quarts de tour. (3) torch.rot90(crops_variable[i, j], int(ks[i,j]), dims=(0,1)) : applique ks[i,j] rotations de 90° au patch (i,j), dans le plan (hauteur, largeur). La compréhension for i ... for j ... parcourt tous les patchs ; torch.stack empile les B*K patchs tournés en un seul tenseur. (4) .view(batch_size, num_crops, I, J) : remet la forme (B, K, I, J). Pourquoi cette augmentation ? Sur un patch carré, rot90 est sans perte d’information (juste une réorientation), et ça force le ResNet local à ne pas mémoriser une orientation fixe → anti-overfit (recette de l’article GMIC).

Reshape pour la branche locale

# === extrait réel : gmic_finetune.py ===
        crops_variable = crops_variable.view(batch_size * num_crops, I, J).unsqueeze(1)  # (1)
        # --- branche locale + MIL attention ---
        h_crops = self.local_network.forward(crops_variable).view(batch_size, num_crops, -1)  # (2)
        z, self.patch_attns, self.y_local = self.attention_module.forward(h_crops)            # (3)

(1) .view(batch_size * num_crops, I, J) aplatit les dimensions image et patch : on traite les B*K patchs comme un gros « batch » de petites images, ce qu’attend un ResNet 2D. .unsqueeze(1) insère une dimension de canal en position 1 → (B*K, 1, I, J) (1 canal, niveaux de gris). (2) self.local_network.forward(...) : le ResNet-18 local extrait un vecteur de features par patch. .view(batch_size, num_crops, -1) re-sépare les patchs par image : (B, K, D) où D est la dimension du vecteur (le -1 la déduit). (3) attention_module.forward(h_crops) : le module MIL attention. Renvoie z (vecteur agrégé pondéré par l’attention), self.patch_attns (les poids d’attention par patch, utiles pour la visu), et self.y_local (proba locale, déjà bornée par l’attention → encore une proba, pas un logit).

Fusion

# === extrait réel : gmic_finetune.py ===
        # --- fusion ---
        g1, _ = torch.max(h_g, dim=2)                                        # (1)
        global_vec, _ = torch.max(g1, dim=2)                                 # (2)
        concat_vec = torch.cat([global_vec, z], dim=1)                       # (3)
        p_drop = self.experiment_parameters.get("dropout", 0.0)              # (4)
        if p_drop > 0:                                                       # (5)
            concat_vec = nn.functional.dropout(concat_vec, p=p_drop, training=self.training)
        self.y_fusion = torch.sigmoid(self.fusion_dnn(concat_vec))           # (6)
        return self.y_fusion, self.y_global, self.y_local, self.saliency_map # (7)

(1)-(2) torch.max(h_g, dim=2) puis torch.max(g1, dim=2) : un global max pooling en deux temps sur la feature map globale h_g. torch.max renvoie un couple (valeurs, indices) ; on ne garde que les valeurs (_ ignore les indices). Deux max successifs réduisent les deux dimensions spatiales (hauteur puis largeur) → global_vec, le résumé vectoriel de la branche globale. (3) torch.cat([global_vec, z], dim=1) : concatène le résumé global et le résumé local z le long de la dimension des features (dim=1) → le vecteur qui nourrit la fusion. (4) self.experiment_parameters.get("dropout", 0.0) : récupère le taux de dropout des hyperparamètres (défaut 0.0 si absent). (5) if p_drop > 0: — applique le dropout seulement s’il est demandé. nn.functional.dropout(..., training=self.training) : le dropout n’agit qu’en entraînement (training=self.training) ; en eval il est neutre. C’est une régularisation train-only sur l’entrée du classifieur. (6) torch.sigmoid(self.fusion_dnn(concat_vec)) : fusion_dnn est le Linear de fusion (produit un logit) ; on lui applique explicitement sigmoid → y_fusion est une proba. C’est ICI que y_fusion devient borné [0,1]. (7) return ... : on renvoie les 3 têtes + la saliency, dans cet ordre. Le reste du pipeline (loss, evaluate) dépend de cet ordre exact.

Piège n°1 du projet (la double-sigmoïde). Les trois sorties sont déjà des probabilités. La loss devra donc être binary_cross_entropy (qui attend des probas), jamais BCEWithLogits (qui ré-applique une sigmoïde). On y revient en détail au §3.1.

2.4 default_parameters — les hyperparamètres d’architecture

# === extrait réel : gmic_finetune.py ===
def default_parameters(percent_t=0.02, gpu_number=0, device_type="gpu", dropout=0.0):  # (1)
    return {
        "device_type": device_type,        # (2)
        "gpu_number": gpu_number,
        "max_crop_noise": (100, 100),       # (3)
        "max_crop_size_noise": 100,
        "cam_size": (46, 30),               # (4)
        "K": 6,                             # (5)
        "crop_shape": (256, 256),           # (6)
        "post_processing_dim": 256,         # (7)
        "num_classes": 2,                   # (8)
        "use_v1_global": False,             # (9)
        "percent_t": percent_t,             # (10)
        "dropout": dropout,                 # (11)

(1) Signature avec valeurs par défaut. Ces valeurs reproduisent celles du run_model.py upstream (modèle ResNet-18 NYU) — on ne change que ce qui est exposé en argument. (2) device_type / gpu_number : où tourne le modèle (GPU 0 ici). (3) max_crop_noise / max_crop_size_noise : bruit aléatoire sur la position/taille des crops ROI (augmentation interne GMIC). (4) cam_size = (46, 30) : la taille de la class activation map (la grille basse-réso de la saliency). C’est le self.cam_size utilisé dans le forward. (5) K = 6 : nombre de patchs ROI extraits (le num_crops du forward). (6) crop_shape = (256, 256) : taille d’un patch — carré (d’où le I == J qui autorise rot90). (7) post_processing_dim = 256 : dimension de sortie du post-traitement. (8) num_classes = 2 : nos deux classes [benign, malignant]. (9) use_v1_global = False : utilise la version V2 du réseau global. (10) percent_t : le t de l’agrégation top-t % (défaut 2 %). Plus il est petit, plus l’agrégation se concentre sur les pixels les plus chauds. (11) dropout : le taux de dropout fusion (celui lu dans le forward (4)).

2.5 build_gmic — construire et charger les poids NYU

# === extrait réel : gmic_finetune.py ===
def build_gmic(weights_path, parameters, device):                                # (1)
    model = GMICTrain(parameters)                                                # (2)
    if weights_path:                                                             # (3)
        state = torch.load(weights_path, map_location="cpu", weights_only=False) # (4)
        missing, unexpected = model.load_state_dict(state, strict=False)         # (5)
        print(f"[build_gmic] charge {weights_path}")
        if missing:                                                              # (6)
            print(f"  missing keys    ({len(missing)}): {missing}")
        if unexpected:                                                           # (7)
            print(f"  unexpected keys ({len(unexpected)}): {unexpected}")
    return model.to(device)                                                      # (8)

(1) Trois arguments : le chemin du checkpoint, les hyperparams (default_parameters), le device cible. (2) GMICTrain(parameters) : instancie notre sous-classe (poids initialisés aléatoirement à ce stade). (3) if weights_path: — on ne charge des poids que si un chemin est fourni (sinon entraînement from scratch). (4) torch.load(..., map_location="cpu", weights_only=False) : - map_location="cpu" : charge le checkpoint en RAM CPU (même s’il a été sauvé depuis un GPU), pour éviter de remplir le GPU avant l’heure et rester portable entre machines ; - weights_only=False : autorise le unpickling d’objets Python arbitraires (et pas seulement des tenseurs). Nécessaire car le checkpoint NYU n’est pas un pur state_dict de tenseurs. (5) load_state_dict(state, strict=False) : injecte les poids. strict=False est essentiel — le défaut strict=True planterait à la moindre clé qui diffère. Renvoie deux listes : missing (paramètres du modèle absents du checkpoint → ils gardent leur init aléatoire) et unexpected (clés du checkpoint absentes du modèle → ignorées). C’est exactement le comportement voulu en transfer learning : réutiliser le backbone, réinitialiser la tête redimensionnée à 2 classes. (6)-(7) On imprime les deux listes : c’est un garde-fou. Si missing contenait ds_net.*, ça signalerait que le backbone n’a pas été chargé. (8) model.to(device) : déplace tout le modèle (poids + buffers) sur le GPU en une fois, et le renvoie.

2.6 _BACKBONE_PREFIXES et param_groups — LR discriminatif

# === extrait réel : gmic_finetune.py ===
# Noms des sous-modules backbone (greffes sur le module parent par add_layers)
_BACKBONE_PREFIXES = ("ds_net", "dn_resnet")                                  # (1)

def param_groups(model, lr_backbone, lr_head):                                # (2)
    backbone, head = [], []                                                   # (3)
    for name, p in model.named_parameters():                                  # (4)
        if not p.requires_grad:                                               # (5)
            continue
        if name.startswith(_BACKBONE_PREFIXES):                               # (6)
            backbone.append(p)
        else:                                                                 # (7)
            head.append(p)
    n_bb = sum(p.numel() for p in backbone)                                    # (8)
    n_hd = sum(p.numel() for p in head)
    print(f"[param_groups] backbone={n_bb/1e6:.2f}M @ lr={lr_backbone} | "
          f"head={n_hd/1e6:.2f}M @ lr={lr_head}")
    return [                                                                   # (9)
        {"params": backbone, "lr": lr_backbone},
        {"params": head, "lr": lr_head},
    ]

(1) _BACKBONE_PREFIXES = ("ds_net", "dn_resnet") : les deux préfixes de noms qui identifient le backbone. Pourquoi seulement deux noms suffisent ? Les classes GlobalNetwork/LocalNetwork héritent d’AbstractMILUnit, qui n’est pas un nn.Module. Donc self.global_network = GlobalNetwork(...) n’enregistre rien dans le state_dict (le __setattr__ de nn.Module ignore les objets non-Module). Les ResNet ne sont enregistrés que par la greffe add_layers() qui fait self.parent_module.ds_net = ... et self.parent_module.dn_resnet = .... Résultat : dans named_parameters(), les poids des deux ResNet apparaissent uniquement sous les préfixes ds_net.* et dn_resnet.*. (2) Trois arguments : le modèle et deux learning rates (backbone bas, tête haute) — c’est le LR discriminatif. (3) Deux listes vides : on va trier les paramètres. (4) model.named_parameters() : itère sur (nom, tenseur) de tous les paramètres. (5) if not p.requires_grad: continue : saute les paramètres gelés. C’est ce continue qui, en mode --freeze-backbone (cf. §2.8), vide complètement le groupe backbone — il n’entre jamais dans l’optimiseur. (6) name.startswith(_BACKBONE_PREFIXES) : str.startswith accepte un tuple de préfixes (vrai si le nom commence par l’un d’eux) → le param va dans backbone. (7) else: head.append(p) : tout le reste (postprocess, attention, fusion) va dans la tête. (8) On compte les params de chaque groupe (p.numel() = nombre d’éléments) et on les imprime en millions — log de contrôle (« backbone=13.98M @ 1e-5 | head=0.13M @ 1e-4 »). (9) On renvoie une liste de groupes au format attendu par les optimiseurs PyTorch : chaque dict a ses params et son lr propre.

2.7 freeze_backbone — le gel (linear-probe)

# === extrait réel : gmic_finetune.py ===
def freeze_backbone(model):                                                   # (1)
    n = 0                                                                     # (2)
    for name, p in model.named_parameters():                                  # (3)
        if name.startswith(_BACKBONE_PREFIXES):                               # (4)
            p.requires_grad = False                                           # (5)
            n += p.numel()                                                    # (6)
    print(f"[freeze_backbone] {n/1e6:.2f}M params backbone geles (requires_grad=False)")

(1)-(2) Fonction qui gèle le backbone ; n comptera les params gelés. (3)-(4) On parcourt les paramètres et on filtre par les mêmes préfixes que param_groups. (5) p.requires_grad = False : le geste central. Trois effets en chaîne : 1. au backward(), aucun gradient n’est calculé pour ce tenseur ; 2. combiné au continue de param_groups (5), il est exclu de l’optimiseur ; 3. autograd ne stocke plus les activations intermédiaires de ces couches → moins de mémoire, forward/backward plus rapides. (6) n += p.numel() cumule le compte ; le print affiche « 13.98M params gelés » sur le vrai run.

2.8 set_backbone_eval — figer la BatchNorm (le piège n°2)

requires_grad=False gèle les poids… mais pas les statistiques de BatchNorm ! Une couche BN garde des buffers running_mean/running_var qui, en mode train(), sont mis à jour à chaque batch — même sans gradient. Un backbone « gelé » verrait donc quand même ses BN dériver vers les stats du domaine RSNA, changeant ses sorties. On fige ça aussi :

# === extrait réel : gmic_finetune.py ===
def set_backbone_eval(model):                                                 # (1)
    for name, module in model.named_modules():                                # (2)
        if name.startswith(_BACKBONE_PREFIXES):                               # (3)
            module.eval()                                                     # (4)

(1) Fonction à appeler après chaque model.train() (cf. §3.7). (2) model.named_modules() : itère sur les modules (≠ paramètres) — indispensable car .eval() est une méthode de module, pas de tenseur. (3) Même filtre de préfixes. (4) module.eval() : bascule training=False sur ce module → la BN utilise ses running_mean/var figées et cesse de les mettre à jour.

Pourquoi le ré-appeler à chaque epoch ? model.train() est récursif : il remet tous les sous-modules (donc la BN du backbone) en mode train. Il faut donc re-figer juste après, à chaque epoch.

3.1 compute_loss et bce — la loss 3 têtes (pièges BCE + .float())

La loss de l’article GMIC supervise les trois sorties + régularise la saliency :

\[ \mathcal{L} = \mathrm{BCE}(y_{fusion}) + \mathrm{BCE}(y_{global}) + \mathrm{BCE}(y_{local}) + \beta\,\lVert \mathrm{saliency} \rVert_1 \]

# === extrait réel : train_gmic.py ===
def bce(prob, target):                                                        # (1)
    prob = prob.clamp(EPS, 1.0 - EPS)                                         # (2)
    return nn.functional.binary_cross_entropy(prob, target)                  # (3)

def compute_loss(y_fusion, y_global, y_local, saliency, target, beta):        # (4)
    l_fus = bce(y_fusion.float(), target)                                     # (5)
    l_glo = bce(y_global.float(), target)
    l_loc = bce(y_local.float(), target)
    l_reg = beta * saliency.float().abs().mean() if beta > 0 else 0.0         # (6)
    total = l_fus + l_glo + l_loc + l_reg                                     # (7)
    return total, {                                                           # (8)
        "loss": float(total.detach()),
        "bce_fusion": float(l_fus.detach()),
        "bce_global": float(l_glo.detach()),
        "bce_local": float(l_loc.detach()),
        "l1_saliency": float(l_reg.detach()) if beta > 0 else 0.0,
    }

(1)-(3) bce(prob, target) : un petit wrapper sûr. (2) prob.clamp(EPS, 1.0 - EPS) borne les probas dans [1e-7, 1-1e-7] → évite log(0) = -inf (la BCE calcule log(prob) et log(1-prob)). (3) nn.functional.binary_cross_entropy(prob, target) : la BCE sur des probas. C’est le piège n°1 : les 3 sorties GMIC sont déjà sigmoïdées (cf. §2.3), donc on utilise binary_cross_entropy et JAMAIS binary_cross_entropy_with_logits. BCEWithLogits ré-appliquerait une sigmoïde en interne → double sigmoïde → gradients écrasés → le modèle collapse. (4) compute_loss reçoit les 4 sorties du forward + la cible + beta. (5) bce(y_fusion.float(), target) : le piège n°2 — .float() hors autocast. L’entraînement tourne en autocast (fp16). Or binary_cross_entropy n’est pas autocast-safe (instable / NaN en fp16). .float() reconvertit en fp32 la sortie avant la BCE. Cet appel a lieu hors du with autocast(...) (cf. §3.7), donc le calcul se fait bien en fp32. (6) l_reg = beta * saliency.float().abs().mean() : la régularisation L1 sur la saliency (|saliency| moyenné), pondérée par beta. Le if beta > 0 else 0.0 évite tout calcul si la régularisation est désactivée. .float() ici aussi. (7) total : la somme des 4 termes — la loss optimisée. (8) On renvoie (total, dict). Le dict contient les valeurs détachées (.detach() coupe le graphe autograd, float(...) ramène un python float) pour le logging sans fuite mémoire. total (tenseur), lui, garde son graphe pour le backward().

3.2 GPUAugment — augmentation kornia sur GPU

Pourquoi déplacer l’augmentation sur GPU ? La VM a 8 vCPU : elle est CPU/IO-bound (décoder les gros PNG sature les workers). En faisant l’augmentation sur GPU, les workers CPU ne font plus que décoder les PNG, et le GPU (sous-utilisé) absorbe l’affine + le gamma. Le flag --gpu-augment fait passer l’occupation GPU de ~49 % à ~91 %.

# === extrait réel : train_gmic.py ===
class GPUAugment(nn.Module):                                                  # (1)
    def __init__(self, input_size=INPUT_SIZE, max_shift=(48, 32)):           # (2)
        super().__init__()
        import kornia.augmentation as K                                       # (3)
        tx = max_shift[1] / input_size[1]                                     # (4)
        ty = max_shift[0] / input_size[0]
        self.affine = K.RandomAffine(                                         # (5)
            degrees=15.0, translate=(tx, ty), scale=(0.9, 1.1),
            p=1.0, same_on_batch=False, padding_mode="zeros")
        self.gamma = K.RandomGamma(gamma=(0.8, 1.25), p=0.5, same_on_batch=False)  # (6)

    def forward(self, x):                                                     # (7)
        mx = x.amax(dim=(1, 2, 3), keepdim=True).clamp(min=1.0)               # (8)
        x = x / mx                                                            # (9)
        x = self.affine(x)                                                    # (10)
        x = self.gamma(x.clamp(0.0, 1.0))                                     # (11)
        return x

(1) GPUAugment(nn.Module) : un module (donc déplaçable sur GPU via .to(device)). (2) max_shift=(48, 32) : translation max en pixels (dy_max, dx_max). (3) import kornia.augmentation as K : kornia fait des augmentations différentiables sur GPU (équivalents GPU des transforms torchvision). (4) kornia attend la translation en fractions de la taille : tx = décalage horizontal max / largeur, ty = vertical / hauteur. Noter l’inversion d’index max_shift[1] (dx) avec input_size[1] (W) — cohérent. (5) K.RandomAffine(...) : une seule affine combinant rotation ±15°, scale 0.9–1.1, translation. p=1.0 (toujours appliquée), same_on_batch=False (transformation différente par image du batch), padding_mode="zeros" (fond noir = le fond du crop mammo, cohérent visuellement). (6) K.RandomGamma(gamma=(0.8, 1.25), p=0.5) : jitter gamma (correction non linéaire de luminance), appliqué une fois sur deux (p=0.5). Pourquoi gamma et pas luminosité/contraste linéaires ? Le z-score en aval (§3.3) annule toute échelle linéaire → seul un gamma non linéaire survit à la normalisation. Noter : pas de hflip — les vues sont déjà normalisées chest-wall-à-gauche. (7) forward(x) : x est un batch float (B,1,H,W), à échelle libre (uint8 [0,255] ou uint16 natif 12 bits). (8) x.amax(dim=(1,2,3), keepdim=True) : le max par image (réduit canaux + H + W, garde la dim pour le broadcast). .clamp(min=1.0) évite la division par 0. (9) x = x / mx : normalise chaque image par son propre max → [0,1]. Ça rend le gamma scale-aware : pour de l’uint8 minmax-stretché (max ~255) c’est comme l’historique /255, pour du 16 bits natif le gamma garde la même force relative. (10) self.affine(x) : applique l’affine GPU. (11) self.gamma(x.clamp(0.0, 1.0)) : clamp garde l’image dans [0,1] (l’affine a pu introduire de légers dépassements) avant le gamma. On renvoie l’image augmentée — le z-score viendra après, dans la boucle.

3.3 gpu_standardize — le z-score par image

# === extrait réel : train_gmic.py ===
def gpu_standardize(x):                                                       # (1)
    x = x.float()                                                             # (2)
    m = x.mean(dim=(1, 2, 3), keepdim=True)                                   # (3)
    s = x.std(dim=(1, 2, 3), keepdim=True, unbiased=False).clamp(min=1e-5)    # (4)
    return (x - m) / s                                                        # (5)

(1)-(2) x = x.float() : convertit en fp32 (l’entrée peut être uint8/int16 → on a besoin de flottants pour la moyenne/écart-type). (3) m = x.mean(dim=(1,2,3), keepdim=True) : moyenne par image (sur canal + H + W). keepdim=True garde la forme (B,1,1,1) pour le broadcast. (4) x.std(..., unbiased=False) : écart-type biaisé (diviseur N, pas N-1) — convention de normalisation d’image. .clamp(min=1e-5) empêche la division par 0 pour une image uniforme. (5) (x - m) / s : le z-score par image — centre à 0, échelle à 1. C’est le standard_normalize attendu par GMIC. Conséquence clé : ça annule toute transformation linéaire d’intensité et toute échelle de bits → c’est pourquoi le dataset peut transférer en uint8/int16 sans normaliser (§4.3) et pourquoi le gamma non linéaire est la seule augmentation d’intensité utile.

3.4 evaluate — AUC par VUE puis agrégation par SEIN

C’est le cœur de la métrique « per-breast ». GMIC s’entraîne par vue, mais l’étiquette clinique RSNA est par sein (un côté = CC + MLO). On évalue donc chaque vue, puis on moyenne les probas des vues d’un même sein.

# === extrait réel : train_gmic.py ===
@torch.no_grad()                                                              # (1)
def evaluate(model, loader, samples, device, beta):
    model.eval()                                                              # (2)
    preds_b, preds_m, preds_gm, preds_lm, labs = [], [], [], [], []           # (3)
    running = 0.0
    n = 0
    for x, y in loader:                                                       # (4)
        x = gpu_standardize(x.to(device, non_blocking=True))                  # (5)
        yt = y.to(device)
        with autocast("cuda"):                                                # (6)
            yf, yg, yl, sal = model(x)
        total, _ = compute_loss(yf, yg, yl, sal, yt, beta)                    # (7)
        running += float(total) * x.size(0)                                   # (8)
        n += x.size(0)
        yf = yf.float().cpu().numpy()                                         # (9)
        yg = yg.float().cpu().numpy()
        yl = yl.float().cpu().numpy()
        preds_b.extend(yf[:, 0].tolist())                                     # (10)
        preds_m.extend(yf[:, 1].tolist())
        preds_gm.extend(yg[:, 1].tolist())  # malignant, tete GLOBAL
        preds_lm.extend(yl[:, 1].tolist())  # malignant, tete LOCAL
        labs.append(y.numpy())                                                # (11)

(1) @torch.no_grad() : décorateur qui désactive autograd dans toute la fonction → pas de graphe, moins de mémoire, plus rapide (on n’apprend pas en éval). (2) model.eval() : bascule tout le modèle en mode éval (BN figées, dropout neutre, et self.training=False → pas de rotation des patchs dans le forward). (3) listes d’accumulation : probas benign/malignant de la fusion (preds_b, preds_m), malignant des têtes global (preds_gm) et local (preds_lm), et les labels (labs). running/n pour la val_loss moyenne. (4) boucle sur le val_loader (séquentiel, cf. §4.4). (5) x.to(device, non_blocking=True) : transfert CPU→GPU asynchrone (non_blocking=True ne bloque que si la mémoire source est page-locked) ; puis gpu_standardize (z-score). Pas d’augmentation en éval. (6) with autocast("cuda"): — on évalue aussi en mixed precision (cohérence avec l’entraînement, et c’est plus rapide). (7) compute_loss(...) pour la val_loss ; on ignore le dict de détail (_). (8) running += float(total) * x.size(0) : somme pondérée par la taille du batch (x.size(0)) → moyenne correcte même si le dernier batch est plus petit. (9) yf.float().cpu().numpy() : reconvertit en fp32, rapatrie sur CPU, passe en numpy (sklearn travaille sur numpy). Idem yg, yl. (10) On extrait les colonnes : [:, 0] = benign, [:, 1] = malignant. .extend ajoute toutes les valeurs du batch à la liste plate. (11) labs.append(y.numpy()) : on garde les labels du batch (concaténés plus loin).

Le piège per-view vs per-breast. Reporter l’AUC par vue surestime souvent la performance clinique (deux vues corrélées du même sein « comptent double »). Le projet reporte et sélectionne par sein (+~0.05 d’écart observé). C’est pour ça que evaluate reçoit samples (pour connaître pid+view de chaque prédiction) et impose l’ordre séquentiel.

(1) On fabrique les hyperparams d’archi (avec le percent_t et le dropout CLI). (2) build_gmic(...) construit le modèle + charge les poids NYU (§2.5). (3) if args.freeze_backbone: freeze_backbone(model) : on gèle AVANT de créer l’optimiseur, pour que param_groups voie déjà requires_grad=False et n’inscrive jamais le backbone. L’ordre est critique. (4) torch.optim.Adam(param_groups(...), weight_decay=...) : Adam avec les deux groupes (LR discriminatif). weight_decay = régularisation L2 sur tous les poids entraînés. (5) warmup_iters = max(1, args.warmup_epochs) : au moins 1 epoch de warmup. (6) LinearLR(start_factor=0.01, end_factor=1.0, total_iters=warmup_iters) : le warmup — monte le LR de 1 % à 100 % linéairement sur warmup_iters epochs. Évite les gros pas instables au tout début (poids tête fraîchement init). (7) CosineAnnealingLR(T_max=epochs - warmup_iters) : après le warmup, le LR redescend en cosinus jusqu’à ~0 sur les epochs restantes — décroissance douce classique. (8) SequentialLR([warmup, cosine], milestones=[warmup_iters]) : enchaîne les deux schedulers — warmup jusqu’à l’epoch warmup_iters, puis cosine. (9) GradScaler("cuda", enabled=use_amp) : gère la mixed precision en multipliant la loss par un facteur d’échelle avant le backward (évite que les petits gradients fp16 ne sous-débordent à 0), puis dé-scale avant le step.

        for k in agg:

4.1 build_samples — aplatir les exams en échantillons par vue

GMIC traite une vue à la fois → l’unité du dataset est la vue, pas l’exam.

# === extrait réel : dataset_gmic.py ===
def build_samples(exam_list, image_dir):                                     # (1)
    samples = []
    for exam in exam_list:                                                   # (2)
        cl = exam["cancer_label"]                                            # (3)
        pid = _exam_pid(exam)
        for v in VIEWS:                                                      # (4)
            fs = exam.get(v) or []
            if not fs:
                continue                                                     # (5)
            path = os.path.join(image_dir, fs[0] + ".png")                   # (6)
            if not os.path.exists(path):
                continue                                                     # (7)
            side = _side(v)                                                  # (8)
            ben = int(cl.get(f"{side}_benign", 0))                           # (9)
            mal = int(cl.get(f"{side}_malignant", 0))
            samples.append({                                                 # (10)
                "path": path, "view": v, "pid": pid,
                "label": np.array([ben, mal], dtype=np.float32),             # (11)
                "malignant": mal,
            })
    return samples

(1) prend une liste d’exams + le dossier d’images, renvoie une liste plate. (2) boucle sur chaque exam. (3) cl = exam["cancer_label"] : le dict des labels (par côté) ; pid = patient. (4) boucle sur les 4 vues possibles. (5) if not fs: continue : si la vue n’existe pas pour cet exam, on saute. (6) path = ...fs[0] + ".png" : chemin du PNG croppé (premier fichier de la vue). (7) if not os.path.exists(path): continue : on ignore les fichiers manquants (robustesse — un exam référencé mais sans image décodée). (8)-(9) On lit le label du bon côté : {side}_benign / {side}_malignant (ex. left_malignant). .get(..., 0) → 0 si absent. int(...) → 0/1. (10)-(11) On crée un échantillon : chemin, vue, pid, label [benign, malignant] en float32 (pour la BCE), et malignant à part (pour les stats / sampler). Noter l’ordre [ben, mal] : c’est lui qui fixe [:, 0]=benign, [:, 1]=malignant partout ailleurs.

4.2 load_and_split3 — split patient en 3 (train/abstain/val)

Le split est au niveau patient (pas vue) pour éviter toute fuite : deux vues d’un même patient ne doivent jamais se retrouver de part et d’autre de train/val. Trois ensembles disjoints : train, abstention (held-out pour un modèle d’abstention futur), val.

# === extrait réel : dataset_gmic.py ===
def load_and_split3(pkl_path, train_frac=2.0/3, abstain_frac=1.0/6, val_frac=1.0/6, seed=42):  # (1)
    with open(pkl_path, "rb") as f:
        exams = pickle.load(f)                                               # (2)
    pid_label = {}                                                           # (3)
    for e in exams:
        pid = _exam_pid(e)
        if pid is None:
            continue
        m = int(e["cancer_label"].get("malignant", 0))                       # (4)
        pid_label[pid] = max(pid_label.get(pid, 0), m)                       # (5)
    uniq = sorted(pid_label.keys())                                          # (6)
    labels = [pid_label[p] for p in uniq]
    def _can_strat(lbls):                                                    # (7)
        npos = sum(lbls)
        return npos >= 2 and (len(lbls) - npos) >= 2

(1) fractions par défaut 2/3, 1/6, 1/6 + seed. (2) charge la liste d’exams depuis le pickle. (3) pid_label : pour chaque patient, a-t-il un cancer malignant ? (pour stratifier le split). (4) m = ...get("malignant", 0) : label malignant au niveau exam (tous côtés confondus). (5) max(pid_label.get(pid, 0), m) : un patient est marqué « positif » si au moins un de ses exams est malignant. (6) uniq : patients triés (déterminisme), labels : leur label dans le même ordre. (7) _can_strat : la stratification n’est possible que s’il y a ≥2 positifs et ≥2 négatifs (sinon train_test_split plante). Garde-fou.

# === extrait réel : dataset_gmic.py (les deux splits) ===
    rest_pids, val_pids = train_test_split(                                  # (1)
        uniq, test_size=val_frac,
        stratify=labels if _can_strat(labels) else None, random_state=seed)
    if abstain_frac <= 0:                                                    # (2)
        train_pids, abstain_pids = list(rest_pids), []
    else:
        rest_labels = [pid_label[p] for p in rest_pids]                      # (3)
        train_size_rel = train_frac / (1.0 - val_frac)                       # (4)
        train_pids, abstain_pids = train_test_split(                         # (5)
            rest_pids, train_size=train_size_rel,
            stratify=rest_labels if _can_strat(rest_labels) else None, random_state=seed)
    train_set, abstain_set, val_set = set(train_pids), set(abstain_pids), set(val_pids)  # (6)
    train_ex = [e for e in exams if _exam_pid(e) in train_set]               # (7)
    abstain_ex = [e for e in exams if _exam_pid(e) in abstain_set]
    val_ex = [e for e in exams if _exam_pid(e) in val_set]
    split_pids = {"train": sorted(train_set), "abstain": sorted(abstain_set),
                  "val": sorted(val_set)}
    return train_ex, abstain_ex, val_ex, split_pids                          # (8)

(1) Étape 1 : on extrait d’abord la validation (test_size=val_frac), stratifiée si possible, avec le seed → val_pids + le reste rest_pids. (2) cas abstain_frac <= 0 : pas de held-out d’abstention, tout le reste part en train. Astuce de comparabilité : la val (extraite en 1) ne dépend que de val_frac+seed → elle reste identique aux runs avec abstention. (3)-(4) Sinon, on calcule la part de train relative au reste : train_frac / (1 - val_frac) (car on veut train_frac du total, pas du reste). (5) Étape 2 : on coupe le reste en train/abstain, stratifié. (6) on convertit en set (recherche O(1)). (7) on reconstitue les listes d’exams par appartenance du pid à chaque set. (8) on renvoie les 3 listes d’exams + le dict des pids (sauvé en json pour que le modèle d’abstention réutilise exactement les mêmes ensembles).

(1) hérite de torch.utils.data.Dataset (interface __len__ + __getitem__). (2) augment : applique-t-on l’augmentation CPU ? (True pour train sans gpu-augment). (3) max_shift=(48, 32) : translation max (dy, dx) en pixels pour l’affine. (4) to_uint8 : si True, on transfère en dtype compact (uint8/int16) et on reporte la normalisation z-score sur le GPU (chemin « frugal » mémoire). (5)-(6) Détection de la profondeur du cache : on lit la 1re image ; si son dtype est uint16 → self.bit16 = True. Cette détection pilote le chemin frugal du loader (§4.4) et le cast dans __getitem__. (7) __len__ : nombre d’échantillons.

# === extrait réel : dataset_gmic.py / _load ===
    def _load(self, path):                                                   # (1)
        im = np.asarray(imageio.imread(path), dtype=np.float32)              # (2)
        if im.shape != self.input_size:                                      # (3)
            import cv2
            im = cv2.resize(im, (self.input_size[1], self.input_size[0]),    # (4)
                            interpolation=cv2.INTER_CUBIC)
        return im

(1)-(2) _load : lit le PNG et le convertit en float32 (pour augmentation/resize). imageio préserve les valeurs natives (0–255 ou 0–4095). (3) if im.shape != self.input_size: : si l’image n’est pas déjà à la bonne taille (les PNG croppés le sont normalement déjà). (4) cv2.resize(im, (W, H), INTER_CUBIC) : redimensionne. Attention à l’ordre : cv2 attend (largeur, hauteur) d’où (input_size[1], input_size[0]). INTER_CUBIC = interpolation bicubique (qualité).

# === extrait réel : dataset_gmic.py / _augment ===
    def _augment(self, im):                                                  # (1)
        import cv2
        H, W = im.shape
        ang = np.random.uniform(-15.0, 15.0)                                 # (2)
        scale = np.random.uniform(0.9, 1.1)
        mh, mw = self.max_shift
        dy = np.random.uniform(-mh, mh); dx = np.random.uniform(-mw, mw)     # (3)
        M = cv2.getRotationMatrix2D((W/2.0, H/2.0), ang, scale)              # (4)
        M[0, 2] += dx; M[1, 2] += dy                                         # (5)
        im = cv2.warpAffine(im, M, (W, H), flags=cv2.INTER_LINEAR,           # (6)
                            borderMode=cv2.BORDER_CONSTANT, borderValue=0.0)
        if np.random.rand() < 0.5:                                           # (7)
            gamma = np.random.uniform(0.8, 1.25)
            vr = float(im.max())                                             # (8)
            if vr > 0:
                im = vr * np.power(np.clip(im, 0.0, vr) / vr, gamma)         # (9)
        return im

C’est l’équivalent CPU de GPUAugment (mêmes transformations). (1) augmentation CPU, utilisée quand augment=True (train sans --gpu-augment). (2)-(3) tirages aléatoires : rotation ±15°, scale 0.9–1.1, translations dy/dx bornées par max_shift. (4) getRotationMatrix2D((W/2,H/2), ang, scale) : la matrice 2×3 de rotation + scale autour du centre. (5) M[0,2] += dx; M[1,2] += dy : on ajoute la translation aux termes d’offset de la matrice → une seule affine combine rotation+scale+translation. (6) cv2.warpAffine(..., BORDER_CONSTANT, borderValue=0.0) : applique l’affine, fond noir (0.0 = fond du crop mammo). Pas de hflip (vues normalisées). (7) if np.random.rand() < 0.5: : gamma une fois sur deux. (8) vr = im.max() : le max de l’image (gamma scale-aware comme en GPU). (9) vr * (clip(im,0,vr)/vr) ** gamma : applique le gamma sur l’image normalisée par son max, puis remet à l’échelle. Non linéaire → survit au z-score.

# === extrait réel : dataset_gmic.py / __getitem__ ===
    def __getitem__(self, idx):                                              # (1)
        s = self.samples[idx]
        im = self._load(s["path"])                                          # (2)
        if self.augment:
            im = self._augment(im)                                          # (3)
        if self.to_uint8:                                                   # (4)
            if self.bit16:                                                  # (5)
                img = torch.from_numpy(np.ascontiguousarray(
                    np.clip(im, 0.0, 32767.0).astype(np.int16))).unsqueeze(0)  # (6)
            else:
                img = torch.from_numpy(np.ascontiguousarray(im.astype(np.uint8))).unsqueeze(0)  # (7)
        else:
            im = im - im.mean()                                             # (8)
            im = im / max(im.std(), 1e-5)
            img = torch.from_numpy(np.ascontiguousarray(im)).unsqueeze(0)   # (9)
        label = torch.from_numpy(s["label"])                                # (10)
        return img, label

(1) retourne (image_tensor, label_tensor) pour un index. (2)-(3) charge l’image, l’augmente si demandé. (4) if self.to_uint8: — le chemin compact (transfert d’un dtype léger, z-score reporté sur GPU). C’est ce chemin qui est utilisé (to_uint8=True par défaut dans make_loaders). (5)-(6) cas 16 bits : torch n’a pas d’uint16 → on passe par int16 (valeurs natives 12 bits ≤ 4095, qui tiennent largement dans int16 ≤ 32767, d’où le clip(im, 0, 32767)). np.ascontiguousarray garantit un buffer mémoire contigu (sinon torch.from_numpy peut refuser). .unsqueeze(0) ajoute la dim canal → (1, H, W). (7) cas 8 bits : simple cast uint8. (8)-(9) chemin non-compact (si to_uint8=False) : on fait le z-score sur CPU ici ((im-mean)/std). max(std, 1e-5) évite la division par 0. (10) label : le tenseur [benign, malignant]. On renvoie (img, label).

Footgun OOM-RAM (le piège n°3). Transférer du float32 full-res (2944×1920×4 octets ≈ 22 Mo/image) avec pin_memory + plusieurs workers + prefetch sature les 94 Go de RAM de la VM. D’où le cache compact (uint8 = 4× moins, int16 = 2× moins) et la normalisation reportée sur GPU. Le z-score GPU étant insensible à l’échelle, le résultat numérique est identique.

4.4 _make_sampler et make_loaders (le chemin frugal 16 bits)

# === extrait réel : dataset_gmic.py / _make_sampler ===
def _make_sampler(samples):                                                  # (1)
    finding = [int(s["label"][0] > 0 or s["label"][1] > 0) for s in samples] # (2)
    n_pos = sum(finding); n_neg = len(finding) - n_pos                       # (3)
    w_pos = 1.0 / n_pos if n_pos else 0.0                                     # (4)
    w_neg = 1.0 / n_neg if n_neg else 0.0
    weights = [w_pos if f else w_neg for f in finding]                       # (5)
    return WeightedRandomSampler(weights, num_samples=len(weights), replacement=True)  # (6)

(1) construit l’échantillonneur équilibré (recette anti-collapse de l’article). (2) finding : 1 si la vue a une lésion (benign OU malignant > 0), 0 sinon. On équilibre « avec lésion » vs « négative ». (3) n_pos/n_neg : nombre de vues avec/sans lésion. (4) w_pos = 1/n_pos, w_neg = 1/n_neg : poids inversement proportionnels à l’effectif de chaque classe → chaque classe pèse autant en tout. (5) weights : à chaque vue, son poids selon sa classe. (6) WeightedRandomSampler(weights, num_samples=len(weights), replacement=True) : tire len échantillons avec remise, proportionnellement aux poids → ~50/50 lésion/négatif par epoch, même si les positifs sont rares. Sans ça, le modèle collapse (prédit toujours « négatif »).

(1) frugal = train_ds.bit16 : on bascule en mode frugal si le cache est en 16 bits (int16 = 2× les octets de l’uint8 → l’empreinte RAM double). (2) pin_memory = not frugal : en 8 bits on épingle la mémoire (transfert GPU plus rapide via non_blocking) ; en 16 bits on désépingle (la mémoire page-locked n’est pas reclaimable → sur cette VM sans swap ça part en reclaim/compaction, 88 % sys, GPU affamé, blocage de fait). (3) prefetch_factor = 1 if frugal else 2 : en 16 bits on préfetche moins (1 batch d’avance par worker) pour borner la RAM ; en 8 bits on garde le chemin rapide (2). persistent_workers=False : les workers sont recréés à chaque epoch (libère la RAM entre epochs). (4) train_loader : sampler=_make_sampler(...) (équilibrage — donc pas de shuffle, mutuellement exclusif avec un sampler), drop_last=True (jette le dernier batch incomplet → tailles régulières, BN stable). (5) val_loader : shuffle=False et pas de drop_last → ordre séquentiel = ordre du dataset. C’est l’invariant exigé par l’agrégation par sein (l’assert len(samples)==len(preds) de evaluate, §3.4). (6) on renvoie les 2 loaders + les listes train/val (ces dernières alimentent l’agrégation par sein).

Pourquoi **loader_kw partagé ? Les mêmes options réseau (workers, pin, prefetch) s’appliquent aux deux loaders ; seul ce qui diffère (sampler vs shuffle, drop_last) est passé explicitement. Le mode frugal est décidé une fois à partir de la profondeur réelle du cache détectée par le dataset.

La recette du pipeline en une phrase
