Comment GMIC prépare vos mammographies

Guide visuel du prétraitement — de l’image brute au format d’inférence

Pourquoi prétraiter ?

Une mammographie brute ne peut pas être envoyée directement au modèle GMIC. Entraîné sur un corpus précis (INbreast / CBIS-DDSM), GMIC s’attend à recevoir des images dans un format très spécifique : taille fixe, fond noir supprimé, niveaux d’intensité normalisés.

Quatre étapes transforment vos images brutes en ce format :

Étape Ce qu’elle fait Où
1. Conversion DICOM → PNG Extrait les pixels du format médical preprocess.py
2. Construction du PKL Organise les examens dans la structure GMIC preprocess.py
3. Recadrage Supprime le fond noir autour du sein preprocess.py
4. Resize 2944×1920 Uniformise la taille de toutes les images preprocess.py
— Flip + normalisation Aligne les seins et centre la distribution inference.py

Le flip horizontal et la normalisation mean/std sont appliqués à la volée lors de l’inférence — inutile de les précalculer ni de les stocker sur disque.

Ce notebook illustre les 4 étapes de prétraitement sur vos images.

Étape 1 — Conversion DICOM → PNG

Les mammographies médicales sont souvent stockées au format DICOM (.dcm), un format qui encapsule bien plus que l’image : identité du patient, paramètres du scanner, métadonnées EXIF…

Cette étape extrait les pixels bruts et les sauvegarde en PNG 16-bit. Elle corrige aussi une particularité de certains scanners qui stockent les niveaux inversés (MONOCHROME1) : sans correction, le tissu mammaire apparaîtrait en noir sur fond blanc — l’inverse de ce qu’attend GMIC.

# preprocess.py · ligne 112
if ds.PhotometricInterpretation == "MONOCHROME1":
    arr = arr.max() - arr   # inverse les niveaux : blanc ↔ noir

Si vos images sont déjà en PNG (comme les données data/raw/sample/), cette étape est ignorée automatiquement.

Les images ci-dessous sont les PNG tels qu’ils arrivent dans votre INPUT_DIR, avant tout traitement. On y voit les 4 vues standard d’une mammographie : CC (cranio-caudale, de dessus) et MLO (médio-latérale oblique, de côté), pour chaque sein (L = gauche, R = droite).

Étape 2 — Construction du PKL GMIC

GMIC n’accède pas aux fichiers image directement : il attend un fichier .pkl (Python pickle) qui décrit tous les examens dans une structure précise.

Pour chaque patient, ce fichier liste : - les chemins vers les 4 images (une par vue), - le label cancer (malignant : True/False), - les métadonnées nécessaires aux étapes suivantes.

Cette étape lit votre train.csv et construit ce fichier pickle. C’est la “colonne vertébrale” que toutes les étapes suivantes vont enrichir.

# preprocess.py · lignes 150–154
"cancer_label": {
    "malignant":       0,   # ← 1 si le patient a un cancer (n'importe quel côté)
    "left_malignant":  0,   # ← 1 si cancer côté gauche
    "right_malignant": 0,   # ← 1 si cancer côté droit
    ...
}

Ces labels sont lus depuis la colonne cancer de votre train.csv et propagés par latéralité. L’inférence les réutilise pour calculer l’AUC-ROC.

Étape 3 — Recadrage (crop_mammogram)

Une mammographie brute contient beaucoup de fond noir autour du sein. Ce fond perturbe GMIC : entraîné sur des images recadrées, il obtient de moins bonnes performances si le fond noir est présent.

crop_mammogram détecte automatiquement le tissu mammaire par seuillage et supprime les bords noirs. Il mémorise dans le PKL la window_location — les coordonnées exactes de la zone découpée dans l’image originale.

# preprocess.py · lignes 210–215
src/cropping/crop_mammogram.py
    --input-data-folder  <png_dir>         # images PNG sources
    --output-data-folder <cropped_dir>     # où écrire les PNG recadrés
    --exam-list-path     <pkl_raw>         # PKL d'entrée (construit à l'étape 2)
    --cropped-exam-list-path <pkl_crop>    # PKL de sortie (avec window_location)
    --num-processes 4                      # parallélisation sur 4 cœurs

crop_mammogram est le script GMIC original — on l’appelle en sous-processus pour réutiliser exactement la même logique que les auteurs du papier.

Étape 4 — Resize 2944×1920 + normalisation

Après recadrage, les images ont des tailles variables selon les scanners (certains produisent 3000×2500, d’autres 2000×1600…).

GMIC a été entraîné sur des images de taille exactement 2944×1920 pixels. Toutes les images sont donc redimensionnées à cette taille, puis normalisées en uint8 (valeurs entières de 0 à 255).

Ces deux contraintes — taille fixe et type uint8 — sont des prérequis stricts : un modèle PyTorch ne peut pas traiter un batch d’images de tailles différentes, et les poids ont été appris avec cette plage de valeurs.

# preprocess.py · lignes 279–280
interp = cv2.INTER_AREA if (h > GMIC_H or w > GMIC_W) else cv2.INTER_LINEAR
img_resized = cv2.resize(img, (GMIC_W, GMIC_H), interpolation=interp)

Pourquoi deux interpolations ? INTER_AREA (réduction) évite l’aliasing quand on rétrécit — il moyenne les pixels voisins. INTER_LINEAR (agrandissement) interpole en bilinéaire quand on agrandit — il est plus doux que le voisin le plus proche.

Récapitulatif

À l’issue des 4 étapes, chaque examen est représenté par :

  • 4 images PNG de 2944×1920 px, normalisées en uint8, dans cropped_images/
  • data.pkl — copie de cropped_exam_list.pkl, prêt pour l’inférence

À l’inférence (make infer), chaque image subit à la volée : 1. Flip horizontal des vues droites (R-CC, R-MLO) — tous les seins regardent à gauche 2. Normalisation mean/std — centre la distribution sur ~N(0,1) pour le modèle
